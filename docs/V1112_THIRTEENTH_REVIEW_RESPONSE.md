## 七项取舍及代价

按实施顺序记录：

1. 旧附件只在完整指纹、父单与组织匹配时读时归一化，文件路径只在格式化层遮盖。代价：不明确的载荷仍是通用证据，授权原始 JSON 仍有存储路径。
2. 仅四个已知动作、匹配的行/父身份和预期单侧包装生成明细结论，其余两侧事实分别计数。代价：畸形、未知或矛盾证据只能显示事实，不能给出确定增删结论。
3. 完整阶段表保留并加父上下文/缺后值说明，与摘要共用分类。代价：完整视图仍是一张合并阶段表，不拆成合成阶段。
4. 不可变明细注册表同时记录编辑能力和标签。代价：新增明细族必须明确注册模型及实际业务编辑器。
5. 历史未记录的行不重建，保留51条缺证据提示。代价：这些旧事件无法恢复当时缺失的行详情。
6. 授权原始 JSON 保留路径，维持源证据。代价：有原始审计阅读权限的人仍能查看存储路径；不宣称所有页面入口均隐藏路径。
7. 动作句只描述记录的行身份，不计算数量、单价或合同影响；金额依据在完整行证据中。代价：财务核对须展开明细，不能只读摘要下结论。

本轮无延后 Minor。既有共享、原因、epoch、合同、审批及分期规则保持；原 `create_payment_plan` 父单级事件的证据扩展未纳入本轮，不能据此宣称全部期次创建证据已覆盖。
