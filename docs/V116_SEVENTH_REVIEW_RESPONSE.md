## 附件、协作与权限边界

附件 epoch 与业务版本各司其职：不回退历史业务版本，不自动修复已因旧版本失效的申请。历史申请仍须明确重新核对；真正改金额、交期或工作流仍按业务版本防并发覆盖。改派本身属于交接业务流转，继续推进交接业务版本，且归档同时推进附件 epoch。

GET 读取不存在的状态时按 epoch=0 处理，不创建行；变更路径在父单锁内创建/比较并更新状态。详情页必须与已显示父单快照一致，否则提示刷新；独立下载遇到一次无害变化可重新取父单并第二次鉴权。既有真实 PostgreSQL 删除/读取竞争更新为独立 epoch 校验，并继续剥离物理清理，验证拒绝来自授权层。

| 情形 | 新上传 | 厂端停止共享 | 厂端读取归档 |
|---|---|---|---|
| 路由启用、当前厂可读交接 | 按原上传岗位/状态 | 本人，或本厂管理人员治理已证明本厂上传文件 | 否 |
| 路由暂停、当前厂可读交接 | 普通双方均禁止 | 同上，保留紧急止损 | 否 |
| 工厂已拒单但仍可读交接 | 不因止损权限恢复上传 | 同上，可止损 | 否 |
| 源店已撤回，工厂无其他独立源端权限 | 不可访问 | 不可访问，不能借止损恢复可见性 | 否 |
| 上传组织未知的旧文件 | 不追认历史归属 | 上传人或有权源店治理；不授予厂端同事治理权 | 否 |

厂端不能停止源店/其他厂/未知来源的同事附件。成员离职或改组织不改变已记录上传归属；操作者还必须满足当前目标组织和数据范围。源店原因按附件所属组织、父单及附件编号匹配审计，批量取回，1→11份文件未引入逐文件原因查询。载荷和用户原因均经过模板转义，工厂单独访问源端审计返回404。

仅归档件继续保留源端证据，`purge_attachments` 只重试已授权删除；不清理归档件或备份。浏览器为验证 W1 仅删除本轮新上传的虚构 PDF7，保留其审计和哈希；未删除历史证据。已下载或已经发出的流无法远程收回。
