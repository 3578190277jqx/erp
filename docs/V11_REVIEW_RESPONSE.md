# 栖木 ERP v1.1 · 评审采纳与市场对标

日期：2026-10-16。基于用户提供的 DeepSeek 评审、仓库复核和官方产品资料实施。本文件区分已实现、部分实现与后续专题，不把竞品能力描述当成实现证据。

## 本轮定位

先完善定制家居门店到工厂的业务数据链：行业计价 → 独立订单明细 → 受控变更 → 生产交接 → 库存执行 → 分期回款。保留已有 Django / Tabler、组织权限、事务、CAS 和审计机制。

评审中两处表述已校正：报价转单缺的是独立订单快照，原报价并未删除；数据库已有外键和唯一列索引，本轮补充的是复合查询索引。

## 市场资料与实际落点

| 官方资料 | 借鉴的业务模式 | 本轮实现 |
|---|---|---|
| [三维家云订单](https://www.3vjia.com/Page/cloudOrder.html) | 门店关注订单生产进度 | 显式交接冻结规格；工厂本地订单与开工、完工回传 |
| [ERPNext 库存预留](https://docs.frappe.io/erpnext/stock-reservation) | 预留与实际出库分开 | 已预留、可用量、释放预留、领料转出库 |
| [ERPNext 付款条款](https://docs.frappe.io/erpnext/payment-terms-template) | 应收按期次、金额、到期日组织 | 三期比例可配置，尾差归末期，FIFO 分摊和逾期天数 |
| [ERPNext 采购收货](https://docs.frappe.io/erpnext/purchase-receipt) | 采购订单与到货凭证分离 | 分批收货凭证、累计实收、在途和超收拦截 |

以上为产品官方公开说明，并非市场份额或独立性能比较。没有复制这些产品的业务源码。30/40/30 是可修改的演示默认值，不是行业统一标准。

## 逐项处理

|---|---|---|

## 从哪里体验

运行 `python scripts/start.py --demo` 会幂等追加 v1.1 示例；手动启动可先运行 `python manage.py seed_upgrade_demo`。不会重置密码或覆盖旧单据。

1. 在报价/订单搜索“白橡”：查看投影面积、免折费用、税额、参考毛利、独立产品快照和分期计划。
2. 门厂交接查看该示例；用管理员或工厂的计划员接单，生成工厂本地生产订单。在该订单上创建 BOM、排程、预留与领料。源订单未付定金时不能开工。
3. 库存页查看可用量与采购在途；采购列表的“部分到货”示例可继续按批收齐。
4. 订单/设计/量尺/安装等详情可上传附件；报价、订单、配送详情有打印入口。
5. 客户/物料列表有 CSV 导入与模板；设计详情有版本操作和历史列表；客户详情可新建跟进记录。

参考成本和毛利只用于估算。示例数据均为虚构，不能直接作为正式业务上线验收。
