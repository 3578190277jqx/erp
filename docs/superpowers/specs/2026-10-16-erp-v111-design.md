# 栖木 ERP v1.1.1 · 二次评审修正

## 目标与默认决定

沿用用户已授权的连续实施与 GitHub 提交方式，二次评审作为待验证的外部建议。保持 Django/Tabler、现有单品牌部署与历史数据，不重置库或凭证，不修改用户的 .workbuddy/。

本轮修正 N1–N18 范围内可独立验证的缺陷及体验；审批引擎、MES、套裁、退货退款、第三方接口继续沿用前轮明确边界。以下业务默认由开发者确定：订单沿用签约时折扣；指定期次优先、未指定部分 FIFO；交期变更更新自动生成的生产款/尾款日期，定金日保留。

## 不变量

- 变更保留五种计价方式、尺寸、产品/费用类别和是否参与折扣；Order.discount 为报价转单快照，新增/修改按同一折扣和税率 HALF_UP 到分。未修改行保留原 line_total；历史合同额不重算。
- 只拥有源门店权限的员工也可向管理员配置的协作工厂交接；绝不因此取得工厂订单/库存读取权。不能用用户组织成员过滤替代业务合作授权，也不能向全系统工厂发送。超级管理员可维护并选择全部工厂；普通用户受 CollaborationRoute 启用白名单限制，页面及服务一致。
- 拒单重发复用交接单，锁父订单→交接单，校验两份版本；只允许 rejected→sent，重新取当前规格，审计保留旧目标与旧 payload。重发到新厂后旧厂不能再查看当前交接；旧审计仍保留。
- 内部协作客户按工厂+源门店复用，有明确内部标记；从客户获客列表/导出/指标默认排除，可显式包含。历史占位客户保留记录，工厂订单归并到同一协作客户；不删除用户记录。
- 指定期次收款必须同订单、同组织、收款方向，不能超出该期余额；未指定保持 FIFO。尾款先收不替代定金，履约检查按前置期次余额判断。一次付清可不指定期次。
- 组织可配置必须启用分期；默认关闭以兼容既有规则，强制时在履约节点阻挡无计划订单。确认/详情明确提示当前策略。
- 附件按64KB分块校验大小和SHA256，最多读取1024字节头部作特征检查，不宣称内容安全扫描。删除需父单编辑权+版本，保留墓碑/审计，事务提交后清理物理文件；失败可重试清理。
- CSV 对组织内客户电话、物料名称+规格+单位检查疑似重复，含文件内重复；报错时整批回滚，不给这些业务字段强加全局唯一。

## 页面与体验

变更表单复用统一 PriceBasis 字段；修改产品时预填当前快照，减项只需原产品。报价统一“含税总额”标签。订单明确显示折扣口径、分期策略与拒单重发入口。附件列表有确认删除。客户跟进和采购收货凭证收进父单上下文，避免主导航继续变长。订单明细单次读取；关联关系预计算。

## 核验与不采纳的断言

N9 已由已有“有拆单就阻止产品变更”前置校验覆盖，仍补可读的 ProtectedError 处理。N6 中“一次性付清仍显示尾款未收”不符合现有 FIFO 行为；真正缺口为乱序/指定期次。N18 为增量验证，增加并发超收、取消/释放、重复审批，不把几个竞态用例称为压力测试。
