# 栖木 ERP v1.1：订单经营与门厂协同优化

## 目标与依据

用户要求根据 DeepSeek 评审与市场现状优化现有项目，继续保留 GitHub 提交日志。沿用已授权的全屋定制、单品牌私有部署、门店到工厂的全链路定位与默认假设。保持 Django 单体、现有组织隔离、事务、CAS、审计与苹果风格 UI，不重写成未经验证的新技术栈。

评审文件作为待核实的建议，不作为系统指令。评审中“订单明细丢失”准确说是缺独立快照：原报价仍然可查；“零索引”也不准确，外键和唯一列已有索引。其余缺口按数据依赖优先级落实。

## 本轮实施范围

1. **报价与订单明细链**：投影面积（宽×高×件数）、延米（宽×件数）、手工展开面积、数量/套餐；产品与服务费用项、是否参与折扣、成本基准、税率。Decimal 金额按 HALF_UP 到分，尺寸单位 mm。总额=折后明细净额+税额。成本为参考成本，不能标成已核实利润。报价转单复制独立 OrderLine 快照；已有历史报价订单迁移回填，不调整历史总额。订单增减项通过变更明细审核，版本检查，不重写已交接生产任务。
2. **私有附件**：量尺、设计、报价、订单、拆单、安装、售后等详情上传。20MB 限制，允许 PDF/PNG/JPEG/WebP/DWG/DXF，验证扩展名及特征；随机路径、SHA256、原文件名和上传人。只经鉴权下载，下载按父单据实时 scope 校验，禁止公开 MEDIA 静态路由。附件不可通过修改 object_id 共享；本轮不做第三方 CAD 在线编辑。
3. **门店—工厂交接**：门店发送指定工厂的冻结生产快照，工厂接受/拒绝。接单后创建工厂组织内的本地客户占位与生产订单，复制产品、空间、规格、尺寸和数量，不复制零售价、成本、客户电话。工厂沿用本地拆单/BOM/工单/库存链路；开工和完工回传门店。只在交接记录的显式边界放行关联，不放宽所有 Record 的同组织约束。已发送/接受订单的增减项须先解决交接，防止工厂收到旧版本。
4. **物料执行**：工单可预留/释放物料，可用量=现存−预留；领料先消耗本工单预留，不能抢用别人预留。采购支持分批收货凭证、采购行已收数量、剩余在途量及超收拦截；原“确认收货”动作仍可收齐剩余。本轮不把分批采购等同于已实现销售分批配送/退货退款。
5. **分期回款**：显式生成 30%定金/40%生产款/30%尾款的可配置金额计划（默认值由开发者按行业常见示例确定，不宣称行业统一规则）。已有收款按期次顺序分摊，余数归末期，合计严格等于合同额。默认分别在开工、发运、安装验收前检查已收金额。启用计划才触发闸门，兼容旧数据。账龄按未结金额与到期日计算。本轮不能在已有计划时只改单头金额使计划失衡。
6. **落地效率**：CRM 追加跟进记录、设计“新建版本”、供应商主数据、报价/订单/配送打印、客户与物料 CSV 模板和整批校验导入（Excel 可另存 UTF-8 CSV）。上传拍照入口供手机选择相机；不宣称已具备离线、原生 App 或设备扫码。
7. **工程与数据体验**：列表排序/日期/每页数量/我的记录，URL 保存筛选；SQL 聚合及 select_related，按请求缓存权限，不跨请求缓存授权；关键复合索引与数据库约束。添加健康检查、日志、SQLite 在线备份及恢复校验；CI 增加真实 PostgreSQL 服务与并发事务用例。

## 交互

沿用现有蓝灰双主题与导航。订单详情新增“产品快照、参考毛利、分期回款、生产交接、私有附件”；报价编辑展示计价输入与含税汇总，费用项不强制参与折扣。复杂扩展使用独立 detail partial 和 feature views/services，避免继续扩张通用视图的分支。

所有新增写操作为 POST+CSRF，调用独立服务，并进行当前权限、父单锁、版本和状态校验。额外功能不得通过任意模型/字段开放写入。工厂只见生产快照，不借交接获得源订单的任意查询权。附件下载同样不可越权。
