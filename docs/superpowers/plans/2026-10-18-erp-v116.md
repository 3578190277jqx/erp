# ERP v1.1.6 Implementation Plan

> Execute inline with superpowers:executing-plans and TDD; one fresh whole-change review at completion.

**Goal:** Resolve W1–W7 after verification, separating attachment epochs, sharing governance and business approval state.
**Architecture:** EvidenceState keyed by parent with epoch CAS under existing parent locks; uploader-origin snapshot and distinct upload/cleanup/stop permissions; scoped audit payload UI; per-request pricing snapshot reused only for GET.
**Tech Stack:** Existing Django5.2, Decimal, SQLite/PostgreSQL16, Chrome.
**Spec:** docs/superpowers/specs/2026-10-18-erp-v116-design.md

## Global constraints
Original feature checkout/PR/push authorization; preserve DB/media/credentials/.workbuddy/output. No new worktree, physical purge, merge or public publish. Existing data/version/amounts not rewritten or guessed. No global pricing/request cache.

## Review focus
- Removing a PDF must not invalidate a pending order change, yet a business edit and attachment read race must still be caught.
- Epoch mutation does not full_clean/save parent, and GET never creates state rows or takes write locks.
- Disabled sharing prevents new files in either direction but preserves scoped emergency withdrawal.
- Multi-org users cannot manufacture a historical uploader organization; factory managers cannot target source/foreign/unknown-origin evidence.
- Reasons and raw audit values never leak through factory-visible timelines or unsafe HTML.
- GET pricing result is used once in that request; POST never trusts it or skips fresh locked verification.

## Ledger
Ruling: Use a separate state table instead of adding a field to every Record subclass — keeps attachment lifecycle out of unrelated models — adds a constant read query and mutation CAS under existing parent lock.
Ruling: Pause both-direction uploads while preserving scoped stop — matches administrative pause without trapping sensitive files — changes prior source-upload policy explicitly.
Ruling: Record uploader organization at upload, leave history unknown — user memberships are not an ownership ledger — factory managers cannot govern unknown-origin legacy files; uploader/source can.
Ruling: Audit details already expose scoped payloads; improve presentation/entry, not add unscoped raw timeline data — report partly incorrect — factory timelines remain metadata-only.
