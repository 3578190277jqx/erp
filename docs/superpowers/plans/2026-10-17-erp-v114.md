## Global constraints
Keep existing data, password, .workbuddy and ignored outputs. Writes use scoped POST/CSRF, reason and versions where applicable. No merge/public deployment. Continue authorized pushes on feat/furniture-erp/PR1.

## Review focus
- An ex-employee's bad file can be stopped by source management without deletion or later auto-sharing.
- A page cannot inherit A's prefilled amount into B; a crafted batch POST cannot bypass per-order comparison.
- Multiple stale change lines can be removed one at a time without rolling back recovery or approving an invalid total.
- Read optimization must not reveal old factory files during revoke/retarget races, and query count must stay flat per parent.
- Missing count is distinct from0; current permissions are rechecked under write locks.

## Ledger
Ruling: Source scoped boss/manager may stop sharing another uploader's file but cannot delete it — solves departing employee governance while keeping evidence ownership.
Ruling: Disable change batches rather than add another monetary approval surface — costs bulk convenience; other modules keep batching.
Ruling: Bind source-context order/organization server-side rather than trust a dropdown event — costs switching orders on that contextual page; use ordinary new form for a different order.
Ruling: Keep the agreed repricing model; no basis-only action is introduced — such a mode needs a separate financial policy.
Ruling: Optimistic reads return no data on repeated version changes; write locks stay on mutations — trades a refresh during contention for replica-safe GETs and privacy.
